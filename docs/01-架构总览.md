# 架构总览

pi 是一个 monorepo，围绕两条主线组织代码：

1. **本地编码代理**（`pi-ai` → `pi-agent-core` → `pi-coding-agent`）：在本地进程内跑一个"状态机 agent"，可调用工具、处理多轮对话、持久化会话。
2. **远程会话协议**（`pi-protocol` → `pi-client` / `pi-server`）：把同一个 agent 会话暴露到远程，客户端通过字节传输（WebSocket、Unix socket）以长度前缀 CBOR 消息驱动会话。

## 分层

```
┌───────────────────────────────────────────────────────────┐
│ pi-coding-agent    CLI / SDK / 扩展 / TUI / RPC / 评测     │
├─────────────────────────────┬─────────────────────────────┤
│ pi-agent-core     agent 循环 │ pi-tui   终端 UI            │
│                   工具执行   │ pi-client 远程会话客户端      │
│                   harness   │ pi-server 会话服务器         │
│                   会话抽象   │ pi-protocol 线协议          │
├─────────────────────────────┴─────────────────────────────┤
│ pi-ai    统一 LLM 接入（provider 集合 + 认证 + 流式事件）   │
├───────────────────────────────────────────────────────────┤
│ pi-telemetry   可观测性契约（零依赖）                      │
└───────────────────────────────────────────────────────────┘
```

## 两大核心抽象

### 1. LLM 接入：Provider / Models（`pi-ai`）

- **Provider** 是具体运行时单元：拥有 id/name、认证方法（apiKey 或 OAuth）、模型列表、流式实现。
- **Models** 是 provider 集合的运行时：注册 provider、解析认证、把每个请求委托给拥有该模型的 provider。
- 所有模型必须支持工具调用（function calling），这是 agent 工作流的硬性要求。

### 2. Agent 运行时（`pi-agent-core`）

- **`Agent`**：有状态的封装，拥有当前 transcript，发射生命周期事件，执行工具，提供 steering / follow-up 队列。
- **底层 `agent-loop`**：单轮"assistant 响应 → 工具调用 → 工具结果"的循环，支持顺序/并行工具执行、重试、early-stop 等钩子。
- **`AgentHarness`**（`src/harness/`）：更底层的、面向持久化与恢复的会话状态机，把会话建模为不可变条目（entry）+ 分支树 + 寄存器，支持崩溃恢复、compaction、导航。它是 `agent-loop` 之外的**另一套独立运行时**，与 coding-agent 的会话实现无关（coding-agent 基于 `Agent` 类 + 自己的 `SessionManager`）。

## 远程协议（`pi-protocol` / `pi-client` / `pi-server`）

- 协议版本 1，二进制消息：4 字节大端长度前缀 + 一段定长 CBOR。
- 客户端首条消息必须是 `hello`（含 `PROTOCOL_VERSION`）；之后是关联的 request/response 信封与服务端事件信封。
- **快照（snapshot）是权威状态**：`ServerSnapshot`（会话元数据 + 模型列表）与 `SessionSnapshot`（transcript、phase、模型、thinking level 等）。`TranscriptProgress` 只是增量 UI 提示，不得并入权威状态。
- 会话所有权通过 `SessionLease`（exclusive/shared）管理，防止多个消费者互相踩踏。

## 数据流示例：交互式提示

```
用户输入
  → coding-agent InteractiveMode（TUI）
  → AgentSession（会话管理、持久化、compaction）
  → Agent（工具循环）
  → agent-loop（LLM 调用）
  → pi-ai Models.streamSimple
  → Provider.streamSimple → 厂商 API（SSE 流式）
  → 事件冒泡回 TUI 渲染
```

## 会话持久化的两个层次

1. **`pi-agent-core` 的会话抽象**（`src/harness/session/`）：定义 `SessionRepository` / `Session` 接口、JSONL 参考实现（write-once 条目 + 寄存器）、内存实现；SQLite 实现由独立包提供（`pi-session-backend-sqlite-node`）。供 harness 运行时与远程会话后端使用。
2. **coding-agent 的 `SessionManager`**：把 `Agent` 会话映射到磁盘上的 session 目录（JSONL 转录 + 元数据文件），支持会话列表、分支、恢复与 HTML 导出。两者互不依赖。
